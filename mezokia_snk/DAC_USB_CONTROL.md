# Управление ЦАП через MEZOKIA и USB

> Это архивное описание двух регистров и 19-битного кадра. Актуальная карта
> четырёх регистров и 24-битного кадра приведена в `DAC_CONTROL.md`.

## Назначение

Top-модуль `mezokia` принимает команды компьютера через FTDI, хранит параметры
ЦАП, циклически возвращает их компьютеру и передаёт в ПЛИС 5510ТС028 по
компактному последовательному соединению. В актуальной схеме общий такт 8 МГц
приходит из ПЛИС 5510ТС028 на вход `CLK_FROM_5510` MEZOKIA через контакт 52.

Начальные значения после включения:

| Параметр | Значение |
|---|---:|
| `step_coeff` | 0 |
| `dac_limit` | `0xFFFF` |

## USB-протокол

Формат пакета сохранён из проектов KMS2/KTA2F:

| Байт | Содержимое |
|---:|---|
| 0 | `0x5E` |
| 1 | `0x4D` |
| 2 | адрес регистра |
| 3 | старший байт длины данных |
| 4 | младший байт длины данных |
| 5 | CRC8 заголовка |
| 6… | данные |
| последний | CRC8 данных |

Многобайтные значения передаются старшим байтом вперёд. Декодер принимает
данные только при правильной CRC. Команда неправильной длины регистр не меняет;
`dac_limit` обновляется атомарно после второго байта.

| Адрес | Длина | Доступ | Значение |
|---:|---:|---|---|
| `0x10` | 1 байт | R/W | `step_coeff`: 0 = 1 операция ЦАП на SYNC, 1 = 10 операций на SYNC |
| `0x11` | 2 байта | R/W | `dac_limit[15:8]`, затем `dac_limit[7:0]` |
| `0x12` | 1 байт | R/W | бит 0: 0 = пила, 1 = треугольник |
| `0x13` | 1 байт | R/W | `fall_rate[2:0]`, крутизна спада треугольника |

Примеры команд:

| Действие | Байты пакета |
|---|---|
| `step_coeff = 1` (10 операций/SYNC) | `5E 4D 10 00 01 68 01 07` |
| `dac_limit = 0xFFFF` | `5E 4D 11 00 02 0A FF FF 24` |

Каждые 100 мс выдаются четыре пакета чтения в порядке
`0x10 -> 0x11 -> 0x12 -> 0x13`. Это текущие реально применённые значения,
а не эхо. SYNC формируется в `soc_top` на 5510ТС028.

## Последовательная передача в 5510ТС028

За один кадр передаются все четыре параметра:

```text
бит 22       биты 22:20       биты 19:4       бит 3  биты 2:0
              STEP_COEFF       DAC_LIMIT       MODE  FALL_RATE
CFG_FRAME  ____/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\________________
CFG_DATA        MSB  ---------------------------->  LSB
```

- длина кадра — строго 23 такта;
- порядок — `{step_coeff[2:0], dac_limit[15:0], wave_triangle, fall_rate[2:0]}`,
  старшим битом вперёд;
- MEZOKIA меняет `CFG_DATA` и `CFG_FRAME` по спаду такта;
- 5510ТС028 считывает их по фронту, запас установки при 8 МГц — 62,5 нс;
- новый кадр отправляется сразу после изменения параметра и повторяется раз
  в 1 мс для автоматического восстановления после перезапуска 5510ТС028;
- короткий или слишком длинный кадр приёмник игнорирует;
- оба параметра применяются одновременно после окончания правильного кадра.

## Распиновка стыка плат

Использован блок MEZOKIA с цепями `DP_IN_N[19..22]`: физически это второй
блок выводов платы MEZOKIA, который при установке попадает на самый левый блок
X74 платы MVEC-PVSK. Соединяются одинаковые номера контактов.

| Сигнал | MEZOKIA | Cyclone III | Контакт | MVEC-PVSK | 5510ТС028 |
|---|---|---:|---:|---|---:|
| `reset_n_to_mezokia` → `RESET_N_FROM_5510` | `DP_IN_P[19]` | `PIN_T10` | 51 | `F_MEZO_14`, X74.1 | `IO[127]` |
| `clk_to_mezokia` → `CLK_FROM_5510` | `DP_IN_N[19]` | `PIN_T11` | 52 | `F_MEZO_13`, X74.2 | `IO_GCLK[152]` |
| `CFG_DATA` → `cfg_data` | `DP_IN_N[20]` | `PIN_T9` | 54 | `F_MEZO_9`, X74.2 | `IO[133]` |
| `CFG_FRAME` → `cfg_frame` | `DP_IN_N[21]` | `PIN_U20` | 56 | `F_MEZO_5`, X74.2 | `IO[131]` |

Эта привязка сверена по листам 6–7 схемы MEZO-GP176 и листу 20 схемы
MVEC-PVSK. Земля передаётся штатными контактами разъёмов.

После появления общего такта `soc_top` удерживает `RESET_N_TO_MEZOKIA` в
активном нуле 100 мс, после чего устанавливает постоянную единицу. В MEZOKIA вход
`RESET_N_FROM_5510` асинхронно устанавливает сброс, а снимается он синхронно
через четыре такта. Управления сбросом через
USB нет. Контакты 51/52 образуют пару `DP19`; резистор R66 между P и N должен
быть не установлен.

Контакты 55, 57 и 58 не используются прошивкой MEZOKIA.

## SYNC и тестовые точки

`sync_strobe` в `soc_top` формирует SYNC локально на 5510ТС028 (32 Гц при
такте 8 МГц). Он используется только внутри 5510ТС028 и больше не передаётся
на MEZOKIA. TP1–TP4 в этой версии не назначены.

## Результаты сборки

Проект собирается по `mezokia.qpf`. После удаления генератора SYNC требуется
повторная сборка в Quartus; прежние SOF/JIC и отчёты Timing относятся к
предыдущей версии. Численные задержки внешнего межплатного соединения в SDC
не заданы; устойчивость стыка обеспечивается выборкой на противоположных фронтах.

Файл `mezokia.cof` настроен на `output_files/mezokia.sof`, но Quartus
9.1 не умеет формировать JIC для EPCQ16 — преобразование следует выполнить в
Quartus 13.1, под который изначально создан проект.
